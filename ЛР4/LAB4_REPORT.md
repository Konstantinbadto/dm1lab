# Отчёт по лабораторной работе № 4

**Дисциплина:** Разработка серверных приложений  
**Тема:** Контейнеризация серверного приложения с использованием Docker и написание оптимального Dockerfile  
**Продолжительность:** 2 академических часа (1 занятие)

## 1. Цель работы
Изучить контейнеризацию с Docker, упаковать серверное приложение вместе с его зависимостями, использовать многоэтапную сборку и освоить основные команды управления жизненным циклом контейнера.

## 2. Используемые технологии
- Docker;
- Node.js 22 Alpine;
- TypeScript;
- Express;
- npm.

## 3. Выполнение работы

### 3.1. Создание `.dockerignore`
Создан `.dockerignore`, исключающий Git-метаданные, локальные переменные окружения, `node_modules`, результаты сборки, логи, кэши, файлы IDE и документацию. Это уменьшает контекст сборки и предотвращает случайное копирование локальных секретов в образ.

### 3.2. Создание многоэтапного `Dockerfile`
В Dockerfile применены два этапа:
1. **builder** — установка зависимостей, копирование исходников и компиляция TypeScript в JavaScript;
2. **runtime** — установка только production-зависимостей и копирование каталога `dist` из этапа сборки.

Используется лёгкий базовый образ `node:22-alpine`. Добавлены `EXPOSE 8080`, команда запуска и Docker `HEALTHCHECK`.

### 3.3. Сборка образа
```bash
docker build -t collection-tracker-api:latest .
docker images
```
Первая команда собирает образ с тегом `collection-tracker-api:latest`, вторая показывает локальные образы.

### 3.4. Запуск контейнера
```bash
docker run --name collection-tracker -d -p 8080:8080 --env-file .env collection-tracker-api:latest
```
Параметр `-d` запускает контейнер в фоне, `-p 8080:8080` публикует порт контейнера на порту 8080 хоста, `--env-file .env` передаёт настройки окружения.

Если `.env` отсутствует, переменные можно передать через несколько параметров `-e`.

### 3.5. Проверка работы
```bash
curl http://localhost:8080/api/v1/health
docker ps
docker logs collection-tracker
```
Endpoint должен вернуть `200 OK` и JSON с `status`, `app_name`, `version`, `environment`, `uptime_seconds`. Команда `docker ps` показывает запущенные контейнеры, а `docker logs` выводит журнал приложения.

Остановка и удаление контейнера:
```bash
docker stop collection-tracker
docker rm collection-tracker
```

### 3.6. Фиксация изменений в Git
```bash
git add Dockerfile .dockerignore README.md LAB4_REPORT.md
git commit -m "feat: containerize collection tracker API with multi-stage Docker build"
git push origin main
```

## 4. Результат
Подготовлены `.dockerignore` и оптимизированный многоэтапный Dockerfile для приложения Collection Tracker API. Образ отделяет инструменты сборки от runtime-окружения, а запуск контейнера позволяет передавать конфигурацию и публиковать порт приложения. Фактическая сборка и запуск должны быть проверены в среде, где установлен Docker.

## 5. Контрольные вопросы

### 1. В чём главное отличие виртуальной машины от Docker-контейнера?
Виртуальная машина эмулирует аппаратную среду и запускает собственную гостевую операционную систему с отдельным ядром. Контейнер изолирует процессы и файловую систему, но использует ядро хостовой ОС. Поэтому контейнеры обычно запускаются быстрее и потребляют меньше ресурсов, хотя изоляция и модель безопасности у них отличаются от виртуальных машин.

### 2. Зачем нужен `.dockerignore` и что будет без него?
`.dockerignore` исключает ненужные файлы из контекста сборки. Без него Docker может отправлять в сборщик большие каталоги `node_modules`, кэши, Git-историю и локальные файлы `.env`. Это замедляет сборку, увеличивает объём контекста и создаёт риск случайного попадания секретов в образ.

### 3. Что такое Multi-stage build и какие преимущества он даёт?
Многоэтапная сборка использует несколько этапов с разными задачами. На этапе `builder` находятся инструменты разработки и исходный код, а на финальный этап копируются только необходимые артефакты и production-зависимости. Это уменьшает размер итогового образа, снижает количество лишних компонентов и сокращает потенциальную поверхность атаки.

### 4. Зачем сначала копировать файлы зависимостей, а потом остальной исходный код?
Docker кеширует результаты каждого слоя. Файлы манифеста зависимостей меняются реже исходников, поэтому зависимости можно установить отдельным слоем. При изменении только кода Docker переиспользует закешированный слой и не устанавливает пакеты заново, что ускоряет повторные сборки.

### 5. Чем отличаются `EXPOSE` и флаг `-p`?
`EXPOSE` в Dockerfile документирует, на каком порту приложение ожидает входящие соединения внутри контейнера; он сам по себе не открывает порт на хосте. Флаг `-p host_port:container_port` при `docker run` настраивает публикацию порта, например `-p 8080:8080`, и делает сервис доступным через порт хоста.
